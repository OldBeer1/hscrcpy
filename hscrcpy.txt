Windows-HScrcpy 落地完整方案（对标 Scrcpy、鸿蒙 VirtualScreen 出流）

整体架构：Windows C 客户端 + 鸿蒙特权二进制服务 (hscrcpy-server) + HDC 端口转发 + 虚拟屏硬编码 H265
适用场景：OpenHarmony / 鸿蒙云手机、定制 ROM、拥有系统签名权限设备；普通消费机无签名无法使用 MANAGE_VIRTUAL_SCREEN 权限
一、整体链路
plaintext
Windows(hscrcpy.exe) <==TCP==> hdc forward <==USB/WiFi(HDC) <==> 鸿蒙 /data/local/tmp/hscrcpy-server
Windows侧：SDL渲染+FFmpeg解码 | 键鼠采集
鸿蒙侧：VirtualScreen创建→Surface绑定系统硬编码器→H265裸流TCP输出 + 输入事件接收注入
二、鸿蒙端：hscrcpy-server（OHOS C/C++，设备侧核心）
1. 权限前置
config.json 申请特权权限，系统签名打包放到 /data/local/tmp/
json
"requestPermissions": [
  {"name": "ohos.permission.MANAGE_VIRTUAL_SCREEN"},
  {"name": "ohos.permission.INPUT_CONTROL"},
  {"name": "ohos.permission.CAPTURE_SCREEN"}
]
2. 关键 API 逻辑（OpenHarmony NDK）
① 创建虚拟屏、绑定编码 Surface
cpp
运行
// 1. 创建虚拟显示器
DisplayId virtualDispId = VirtualScreenManager::GetInstance().CreateVirtualScreen(
    "hscrcpy_vdisp", width, height, dpi, nullptr);
// 2. 获取虚拟屏输出Surface
sptr<Surface> encoderSurface = VirtualScreenManager::GetInstance().GetSurface(virtualDispId);

// 3. 绑定OH_AVCodec硬件编码器(H265)
OH_AVCodec *codec = OH_AVCodec_CreateByMime("video/hevc", true);
OH_AVCodecConfig_SetSurface(codecConfig, encoderSurface);
// 编码器启动后，系统桌面合成画面自动灌入Surface，无需主动读帧
核心优势：系统合成直入编码器，零 CPU 拷贝，和 Android MediaProjection 逻辑一致
② TCP 裸流输出
开启 TCP Server (默认监听 8888)，HDC 转发 hdc forward tcp:8888 local:8888
编码器回调OH_AVCodecOnNewOutputData中直接把 H265 裸流通过 socket 发送至客户端
③ 键鼠输入注入
客户端 TCP 第二条通道 (8889) 下发协议：
plaintext
type(1B)+x(4B)+y(4B)+action(1B) // 0:down 1:move 2:up
鸿蒙端调用 InputManager::InjectTouchEvent() / InjectKeyEvent() 注入系统输入
3. 编译产物
OHOS 交叉编译 → hscrcpy-server 静态二进制，无依赖，推送设备：
bash
运行
hdc push hscrcpy-server /data/local/tmp/
hdc shell chmod 755 /data/local/tmp/hscrcpy-server
三、Windows 客户端：hscrcpy.exe（C/C++，单文件，无第三方运行库）
依赖选型（对标 scrcpy 原生）
SDL3：窗口、键鼠捕获、硬件渲染
FFmpeg avcodec+avformat：H265 软 / 硬解码 (D3D11VA 硬解)
内嵌调用hdc.exe做设备枚举 + 端口转发（同 adb）
编译用 MinGW/VS 静态链接，打包单 exe
1. 客户端启动流程伪代码
c
运行
//1. 调用hdc.exe devices枚举在线鸿蒙设备
RunProcess("hdc.exe devices", out_buf);
//2. 执行端口转发
RunProcess("hdc.exe forward tcp:8888 local:8888");
RunProcess("hdc.exe forward tcp:8889 local:8889");
//3. hdc后台启动服务端
RunProcess("hdc.exe shell /data/local/tmp/hscrcpy-server &");

//4. 双socket连接
int video_fd = connect("127.0.0.1",8888); //视频流
int ctrl_fd = connect("127.0.0.1",8889);  //控制通道

//5. FFmpeg打开H265裸流解码器
AVFormatContext* fmt_ctx = avformat_alloc_context();
avformat_open_input(&fmt_ctx,"tcp://127.0.0.1:8888",NULL,NULL);
//6. SDL解码渲染循环 + 键鼠事件捕获转发到ctrl_fd
2. 可选附加功能（复刻 Scrcpy）
动态改分辨率：客户端参数-w 1280 -h720，下发指令重启虚拟屏
剪贴板同步：客户端 / 鸿蒙双向剪贴板透传
文件拖拽推送：拖拽文件→hdc push 到鸿蒙路径
音频采集：鸿蒙 AudioCapturer 采集，AAC 编码同流输出

hscrcpy.exe
五、关键坑 & 优化（云手机场景专用）
VirtualScreen 销毁：客户端退出时 TCP 断开，服务端捕获异常自动 DestroyVirtualScreen，避免系统残留虚拟显示器
编码参数优化：固定帧率 30/60，CRF 动态码率，适配云手机带宽
HDC 无线连接：hdc connect 192.168.xxx.xxx:5555 实现无线投屏
解决之前你遇到的编译多核跑不满：
客户端 / 服务端 CMake 编译拆分子模块，分开并行编译，-j完全吃满 CPU
六、精简协议定义（控制通道 8889）
表格
指令	长度	说明
0x01	1+4+4+1	触屏 (x,y,action)
0x02	1+2	按键 (kecode,press)
0x03	1+4+4	修改分辨率 (w,h)
0x04	N	剪贴板字符串

先编译最小版 hscrcpy-server：仅创建虚拟屏 + H265 编码 + TCP 出流，先通画面

迭代加上键鼠注入、参数配置、剪贴板、文件拖拽
打包单 exe，内嵌便携版 hdc.exe 做成绿色软件
